# 玩家数据记录完善 · 讨论记录

日期：2026-11-17。

状态：用户要求“先记录，不开始制作”。本文件记录当前检查结论与待讨论方向，不是开发指令或已确认的实现方案；不修改现行玩法、数值、数据结构或服务器配置。

## 讨论背景

用户希望前一小时持续有事情可做，提出通过喂养加速前期养成，并考虑增加任务系统建立玩家目标。喂养效果、次数、费用、任务结构和奖励均未定案。

为了后续判断这些方案是否改善体验，需要补足玩家行为和经营过程的数据记录。

## 当前检查结论

本次检查依据为阿里云部署发布包、数据库结构及迁移时的存档样本，尚未实时逐户核验线上存档，也未核查服务器全部定时任务或云端备份设置。

| 数据范围 | 当前已有内容 | 主要缺口 |
| --- | --- | --- |
| 账号与登录 | 账号标识、密码哈希、登录会话及过期时间 | 缺少完整登录历史，现有会话会过期或被退出操作删除 |
| 当前经营进度 | 金币、经验、在店动物、成长时间、研究、订单和比赛等状态 | 当前状态不能完整还原玩家经历的全过程 |
| 成交记录 | 时间、渠道、动物编号、逐只金额、总额 | 缺少覆盖全部金币收支的统一流水与前后余额 |
| 成功操作 | 请求编号、操作类型与参数、结果和状态版本 | 缺少统一事件时间及完整失败记录，回执不能替代行为日志 |
| 引导与在线 | 引导完成标记、最近回店信息和用于业务计时的心跳状态 | 缺少每步耗时、完整在线时段、中途退出及等待原因 |
| 动物履历 | 在店动物档案、当前繁育及最近一窝等信息 | 出售后完整档案与历次繁育历史不完整 |
| 持续备份 | 已有迁移副本，生产使用持久化数据库 | 部署脚本未配置定时异机备份；迁移副本不能替代持续备份 |

现有数据可以统计部分资产、销售情况及首次交易耗时；尚不足以可靠定位首小时空档、引导流失与资源卡点。普通存档、操作回执、行为分析和备份应分别看待。

## 待讨论的补充方向

1. **行为时间线**：记录登录、在线时段、引导各步骤、繁育开始和出生、交易及失败原因。喂养和任务若后续采用，应同步规划相应事件。在线心跳宜汇总为时段，不能直接将连接或挂机当作有效操作。
2. **资产流水与动物履历**：记录金币变化的原因及前后余额，关联同一次操作；保留动物出生、成长、繁育、出售或回收的必要历史。避免重复请求形成重复统计。
3. **持续备份与恢复验证**：讨论定时一致性备份、异机保存及恢复检查。频率、保留期限、保存位置与恢复目标均待确定，不能仅依赖同机文件或迁移副本。

## 后续希望回答的问题

- 玩家前一小时的在线、操作和等待各占多少时间？在哪一步退出？
- 首次繁育、出生、成熟、交易及再次繁育分别耗时多久？
- 空档来自成长等待、种源不足、金币不足、功能门槛，还是目标不清楚？
- 加入喂养或任务后，空档、完成率和继续游玩的情况是否改善？

事件字段、统计口径、保存期限、查询方式、性能开销及记录范围均需后续讨论。记录中不应包含明文密码或完整登录凭证。
