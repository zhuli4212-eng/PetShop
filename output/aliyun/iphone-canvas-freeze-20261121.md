# iPhone 卡死问题与 21.8 真机验收

2026-11-21（北京时间）。**21.8 已通过本次真机复测，原卡死现象未再复现。** 游戏源代码为 `a5d4ef6`，香港正式服于 11:53 发布。用户在外网使用 iPhone 和诊断账号复测后确认游戏已正常。[21.8 发布与验收记录](deployment-20261121.8-hk.json)

## 故障证据

| 时间 | 证据 |
| --- | --- |
| 03:00:46 | iOS 27.2.1 的 `JetsamEvent-2026-11-21-030048.ips` 记录一条活动中的 `com.apple.WebKit.GPU` 进程 `highwater` 事件。另两份较早或相邻的报告没有同类 GPU 终止记录。 |
| 10:49:12 | 21.6 正式程序已将 iPhone 画布降到 1×。当次会话实际采样为 390×651、WebGL 2，随后收到 `webglcontextlost`。同一检查窗口有 6 次 API 请求返回 HTTP 200，未触发请求等待告警。 |
| 12:01:40–12:02:10 | 21.8 诊断入口收到 780 条浏览器事件，19 次页面跳转完成。实际采样为 780×1398、2×、WebGL 2，未记录上下文丢失、脚本错误或未处理的 Promise 拒绝。从 21.8 发布到本次核查，该账号有 46 次 API 请求返回 HTTP 200，未触发请求等待告警。 |

03:00 的系统报告和 10:49 的上下文丢失来自两次不同的时段。12:01 的真机复测使用用户反馈和服务器收到的浏览器诊断事件，现场没有 USB 采集。

## 原因判断与处理

已确认的直接故障是 iPhone 上 WebGL 上下文丢失后游戏画面卡住。最可能的触发因素是 WebKit 在 Canvas 2D 使用自定义字体绘制变化文字时增加 GPU 进程内存占用。旧版降到 1× 后仍复现，21.8 把游戏内 Canvas 文字改用系统字体后，以 2× 通过同一账号的真机复测。这个结果与 WebKit 对相同字体路径的缺陷报告相符。现有真机数据没有连续 GPU 内存曲线，具体内存增长过程仍是原因推断。[WebKit Bug 324693](https://bugs.webkit.org/show_bug.cgi?id=324693)

21.8 在实际线上 21.7 的基础上保留自由市场筛选。三套原字体仍按现有启动流程注册，iPhone 游戏 Canvas 绘制改走系统字体。本地 Chromium 与 WebKit 模拟均完成登录、画布和市场筛选检查，实际文字绘制中自定义字体调用均为 0。
